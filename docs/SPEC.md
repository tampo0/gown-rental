## 3. Бизнес-правила

### 3.1. Период и стоимость

- `итого = ступень(всего) × взрослые + цена_детской × детские − скидка`; скидка = одна взрослая (или детская, если взрослых нет) при количестве ≥ 20. Все цены — в настройках.
- Цена не зависит от длительности (3 часа или сутки для другого города).
- Доставка бесплатная и доступна только при количестве ≥ 100. Суммы сохраняются в брони.

### 3.2. Наличие (главный алгоритм)

Для цвета `c`, размера `s` и периода `[from, to]`:

1. Если размер `s` не предлагается для цвета `c` → свободно 0.
2. Взять все позиции `(c, s)` из броней с активным статусом, чьи даты пересекаются с периодом
   (`b.date_from ≤ to` и `b.date_to ≥ from`), кроме редактируемой брони.
3. Для каждого дня `d` периода: `занято(d) = Σ количество позиций, где b.date_from ≤ d ≤ b.date_to`.
4. `свободно = max(0, склад(c, s) − max_d занято(d))`.

Следствия: день возврата занят; со следующего дня мантия свободна; буферных дней нет.

### 3.3. Сохранение брони

1. Проверить данные (раздел 3.4). Если есть ошибки — вернуть их все, ничего не сохранять.
2. Захватить блокировку (`GET_LOCK('gr_booking_lock', 10)`), чтобы проверка и запись шли атомарно.
3. Если статус активный — проверить наличие каждой позиции. Не хватает хотя бы одной — отказ целиком.
4. Посчитать суммы, сохранить бронь и заменить её позиции.
5. Отпустить блокировку.

Смена статуса на активный повторяет шаг 3 для этой брони.

### 3.4. Проверка данных

- Имя обязательно; телефон — не меньше 10 цифр.
- Статус и источник — из справочников.
- Хотя бы одна позиция; цвет и размер из справочников и размер предлагается для цвета; количество 1…500.
  Одинаковые «цвет + размер» объединяются.
- Даты корректные, возврат не раньше получения, не дольше 30 дней.
  С сайта — ещё и не в прошлом.
- Время начала, если указано, — `HH:MM`; с сайта — только из списка 9:30…15:00 и не в прошлом.
- Доставка → не меньше 100 мантий и обязателен адрес.
- С сайта: обязательно согласие на обработку персональных данных; статус всегда `new`,
  источник `site` — их задаёт сервер, а не браузер. Заполненное скрытое поле-ловушка → ответ «успех» без сохранения.

## 4. Данные

Три таблицы — см. ER-диаграмму в `README.md`.

- `inventory(color, size, quantity)` — уникальная пара `(color, size)`.
- `bookings(...)` — клиент, даты, получение, суммы, источник, статус, комментарий, даты создания и изменения.
- `booking_items(booking_id, color, size, quantity)` — позиции брони.

## 5. Интерфейс сайта (AJAX)

Все запросы — `POST` с `nonce`.

### `gr_quote` — наличие и стоимость

Запрос: `date` (ГГГГ-ММ-ДД), `time` (ЧЧ:ММ, 9:30…15:00), `items` (JSON `[{color, size, quantity}]`).

Ответ:

```json
{
  "success": true,
  "data": {
    "matrix": { "red": { "kids": true, "standard": true, "giant": false }, "purple": { "standard": true } },
    "short":  ["red|standard"],
    "totals": { "quantity": 4, "unit_price": 3000, "free_gowns": 0, "rental": 12000, "delivery_fee": 0, "pickup_fee": 0, "total": 12000, "free_delivery": false }
  }
}
```

- `matrix` — только `true / false` (есть хоть одна мантия). **Точные остатки клиенту не отдаются.**
- `short` — позиции из запроса, которых не хватает в нужном количестве (без чисел).
- Ошибка дат: `{ "success": false, "data": { "message": "…" } }`.

### `gr_submit_booking` — создать бронь

Запрос: `date`, `time`, `items`, `delivery`, `address`, `customer_name`, `phone`, `email`,
`note`, `consent`, скрытое `website`.

- Успех: `{ "success": true, "data": { "id", "date", "time", "items", "quantity", "unit_price", "free_gowns", "total", "delivery", "address", "phone" } }` — из этого страница строит квитанцию; письма отправлены.
- Ошибка: `{ "success": false, "data": { "errors": ["…"] } }`. Сообщения о нехватке — без количества.

### Админка: `gr_set_status`

Запрос: `id`, `status`, `nonce` (админский). Требует права администратора.
Ответ: успех или `{ "message": "…" }` (например, «мантий не хватает»).

| Страница | Содержание |

## 7. Админка

- **Брони:** фильтры (статус, цвет, размер, даты, поиск по имени и телефону), смена статуса в списке
  без перезагрузки (с откатом и сообщением, если мантий не хватает), форма брони с несколькими позициями,
  удаление. Ссылка на WhatsApp клиента.
- **Склад:** таблица цвет × размер, «занято сегодня», итоги; у отсутствующих размеров — прочерк.
- **Настройки:** раздел 2.

## 8. Письма

- Администратору: номер брони, клиент, позиции, даты, получение, суммы, ссылка на WhatsApp клиента и на бронь в админке.
- Клиенту (если указал email): подтверждение заявки с тем же содержанием.
